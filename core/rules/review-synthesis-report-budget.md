# 리뷰 종합의 80줄 작성 예산

## 계산 범위

- 제한은 최종 보고서 전체 80줄이다. 제목·빈 줄·목록·코드 fence·앞뒤 안내 문장도 센다.
- UI의 자동 줄바꿈은 세지 않는다. 실제 개행 기준 `len(report.splitlines())`를 사용한다.
  마지막 개행 하나를 새 빈 줄로 추가 계산하지 않으며, 실제로 남긴 빈 줄은 포함한다.
- 초안 목표는 72줄로 잡아 최종 수정 여유를 남긴다. 예산은 메타·렌즈·판정 20줄,
  완전한 방법 비교 30줄, 근거·한계·coverage 14줄, 다음 행동 8줄을 기본으로 한다.
  실제 후보 수와 중요도에 따라 재배분하되 최종 합계는 80줄 이내여야 한다.

## 작성 순서

1. 실제 보고할 항목을 정하고 가장 중요한 방법 비교에 먼저 충분한 줄을 배정한다.
2. 선택 이유·얻는 점·감수할 점, 후보별 설명·장점·단점, 소제목과 필수 개행을 보존한다.
   비교 후보 수를 줄 수에 맞춰 조작하지 않는다. 제안과 실제 채택도 구분한다.
3. 나머지 정보를 작성한다. 모든 렌즈의 ID·상태·미실행 이유, finding의 source와 근거,
   disposition·eligible, 로컬/원격 구분, 실행 방식·건수, 미확인 한계를 빠뜨리지 않는다.
4. 전체 초안을 합친 뒤 출력 전 줄 수 확인을 수행한다. shell/Python 등 읽기 전용 계산
   도구를 사용할 수 있으면 최종 출력과 동일한 문자열을 메모리에 넣고 계산을 반드시 실행한다.
   눈으로 추정하거나 부분 블록만 세는 것으로 대신하지 않는다. 별도 proof 파일은 필수가 아니다.
5. 80줄 초과 시 아래 순서로 다시 작성하고 다시 센다. 계산 결과를 받은 뒤에는 검증한 문자열을
   그대로 최종 응답으로 반환한다. 측정 후 수정하면 다시 계산하며 안내·결론을 덧붙이지 않는다.
   도구를 사용할 수 없으면 72줄 예산으로 자체 점검하되 도구 검사를 실행했다고 주장하지 않는다.

읽기 전용 계산 예시(실제 완성한 보고서 전체를 report에 넣는다):

```python
report = """<최종 응답 전체>"""
line_count = len(report.splitlines())
print(line_count)
assert line_count <= 80
```

줄 수를 출력한 결과는 보고서 본문에 다시 덧붙이지 않는다. 도구 사용 증거는 실행 기록에 남으며,
사용자에게 별도 승인이나 새 proof 파일 생성을 요구하지 않는다.

## 설명을 잃지 않고 줄이는 순서

- 같은 결론을 앞 요약·반영 상태·방법 비교에서 반복 설명하지 않는다. 한 곳에 설명하고
  다른 곳에서는 상태나 항목명으로 참조한다. 원문 렌즈 아티팩트는 재작성하지 않는다.
- 내용 없는 섹션은 `필수 문제: 없음`처럼 제목과 상태 한 줄로 쓴다. 불필요한 서문·맺음말,
  동일 근거의 재인용, 빈 템플릿, 연속된 빈 줄을 제거한다.
- 상태와 이유가 같은 렌즈는 ID를 빠짐없이 나열해 같은 항목으로 묶을 수 있다.
  서로 다른 상태·실패 이유를 합치거나 렌즈를 생략하지 않는다.
- 불필요한 설명을 제거해도 사실·근거·잔여 위험·coverage를 읽을 수 있어야 한다.
  긴 문장 하나로 몰아넣기, Markdown 목록의 필수 개행 제거, 비교 설명의 한 줄 압축,
  선택 이유나 장단점 삭제는 분량 절약으로 인정하지 않는다.
- 그래도 넘으면 다른 독립 항목의 전체 설명을 허용된 로컬 아티팩트에 옮기고, 본문에는
  항목명·상태·이관 사실·경로를 남긴다. 저장 권한이 없으면 후속 응답으로 분할하고
  현재 보고서가 부분 보고임과 남은 항목을 명시한다. 각 응답도 80줄 이내로 작성한다.
  한 방법 비교 블록은 완전하게 유지하고, 아직 작성·실행하지 않은 아티팩트를 연결하지 않는다.

## 종합 담당자에게 전달할 계약

coordinator와 하위 종합 단계에도 이 지침의 경로와 전체 응답 80줄 제한을 전달한다.
coordinator가 만든 본문에 호스트가 렌즈 상태·검증 결과·다음 행동을 추가했다면,
추가 후의 최종 응답을 다시 센다. 하위 결과가 80줄 이내였다는 사실만으로 종료하지 않는다.

## 완료 확인

- 최종 응답 전체가 80줄 이내인가.
- 남긴 방법 비교의 선택 이유·후보별 설명·장단점과 필수 개행이 온전한가.
- 모든 렌즈·상태·근거·triage·실행 한계가 남았는가.
- 이관·분할한 경우 그 사실을 밝히고 전체 완료로 과장하지 않았는가.
- 줄 수 검사는 새 실행 권한·승인 gate·필수 proof 파일을 만들지 않았는가.
