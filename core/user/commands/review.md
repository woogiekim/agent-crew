# /review — Independent read-only code review

구현 컨텍스트와 분리된 **독립 리뷰 패스**(read-only 서브에이전트)로 아래 대상에 대한 코드 리뷰를 수행해줘: $ARGUMENTS

---

독립 리뷰는 구현 담당자와 분리된 읽기 전용 검토로 수행한다. 사용 가능한 호스트의
독립 리뷰 기능을 사용하고, 실행하지 못하면 미실행 이유를 표시한다. 프로젝트 규약과
아래 리뷰 포커스를 적용하며 빌드·테스트 증거도 구분한다. 이 명령은 특정 호스트의
methodology 파일을 필수 의존성으로 삼지 않는다.

## 기본 동작

- base 브랜치는 **자동 감지**한다 (`git symbolic-ref refs/remotes/origin/HEAD` → 없으면 `main`/`master`/`develop` 순으로 탐색).
- `$ARGUMENTS`가 **비어 있으면** → 현재 브랜치의 변경분(`git diff <base>...HEAD` + staged + 미스테이징)을 전체 리뷰 대상으로 삼는다.
- `$ARGUMENTS`가 **파일/디렉터리 경로**면 → 해당 경로만 리뷰.
- `$ARGUMENTS`가 **커밋 SHA / 레인지**(`abc1234` 또는 `abc..def`)면 → 해당 변경분만 리뷰.
- `$ARGUMENTS`가 **모듈명**(예: `apps/web`, `lib/core`)이면 → 그 모듈 전체 리뷰.

## 절차

1. **컨텍스트 수집** (직접 수행, 에이전트 기동 전)
   - base 브랜치 감지 후 `git status`, `git log <base>..HEAD --oneline`로 최근 커밋/변경 범위 확인
   - 필요 시 `git diff --stat`으로 변경 규모 파악
   - 프로젝트 규약 문서(`CLAUDE.md`/`AGENTS.md`)의 경계·규칙 파악 (리뷰 기준)
   - 변경 파일이 **0건이면** 바로 종료 ("검토할 변경 없음" 출력)

2. **독립 리뷰 수행** (구현과 분리된 read-only 서브에이전트 = `code-reviewer`)
   - 리뷰 서브에이전트에게 전달할 프롬프트에 다음을 포함:
     - 리뷰 대상 경로/레인지/커밋
     - `git diff` 핵심 청크 또는 대상 파일 목록
     - 브랜치명, 감지된 base 브랜치
     - 프로젝트 규약 문서 경로 + 확인 필수 체크리스트 (아래 ## 리뷰 포커스)
     - 공통 방법 비교 지침 경로와 적용 요구 (아래 ## 방법 비교와 트레이드오프)

3. **리포트 후처리**
   - 에이전트 결과를 그대로 출력
   - 말미에 **"다음 액션 제안"** 1~3줄 추가

## 리뷰 포커스 (에이전트 프롬프트에 반드시 포함 — 프로젝트 규약 기준)

### 아키텍처 경계 (최우선)
- 비즈니스 레이어가 DB/큐/검색에 직접 접근했는가
- 데이터 레이어에 비즈니스 로직이 섞였는가
- 허용되지 않은 모듈 간 의존이 생겼는가 — 조합은 규약상 위치(컨트롤러/리졸버)여야 함
- 공개 경계 파라미터가 raw DTO가 아닌 도메인 타입인가 (규약상 요구 시)

### 데이터 / 트랜잭션
- Read/Write 트랜잭션·세션 의미가 올바른가 (read-only 포함)
- 트랜잭션 범위 미지정(기본값) 케이스
- 스키마/컬럼 컨벤션, 규약상 금지된 DB 제약 신규 추가 여부

### 외부 호출
- Timeout / ConnectTimeout 설정
- 업스트림 에러 → 도메인 예외 변환
- 비멱등 요청에 재시도 적용되었는가

### API 계약
- 스키마-핸들러 시그니처 일치
- N+1 / 배치 로딩 누락
- 조합 로직 위치가 규약과 일치하는가

### Security
- 시크릿 하드코딩
- 서명/인증 검증 우회 가능성
- 입력 검증 누락
- 에러 응답에 스택트레이스/내부 구조 노출

### 테스트
- 프로젝트의 테스트 프레임워크/스타일·네이밍 규약 준수
- 슬라이스/단위 우선, 무거운 통합 테스트 남용 없음
- 신규 도메인/정책 로직에 테스트 추가되었는가

## 방법 비교와 트레이드오프

출력을 작성하기 전에 공통 지침 `core/rules/review-method-comparison.md`를 읽고 적용한다.
설치 환경에서는 `~/.agent-crew/rules/review-method-comparison.md`를 읽는다.
실제 방법명, 채택/권장/판단 보류 구분, 선택 이유, 얻는 점·감수할 점, 빈 줄과
`방법별 비교` 소제목, 후보별 설명·장단점, 확인 근거와 한계를 포함한다.
방법명이나 후보 개수를 고정하지 않는다. 방법 선택이 없는 항목에는 비교를 만들지 않는다.
이 형식은 보고서·분석·계획·인계·반영 노트의 서술에 적용하며, 원문 인용과 원시 증거,
프로토콜 필드, 상태·반영률·승인·실행 경계는 바꾸지 않는다.

## 출력 형식 (에이전트가 아래 구조로 리턴)

```markdown
## Code Review Summary

**Risk Level**: LOW / MEDIUM / HIGH / CRITICAL
**Scope**: <검토 대상>
**Files Reviewed**: N

### Must Fix (머지 차단)
- `file:line` 문제 → 수정 제안

### Should Fix (다음 이터레이션)
- `file:line` 문제 → 수정 제안

### Suggestions (개선 제안)
- `file:line` 아이디어

### Good Practices
- 준수 항목 간단히
```

## 다음 액션 제안 (커맨드 말미)
- Must Fix 있으면 → `/fix <대상>` 또는 직접 수정 후 재실행
- Risk LOW/MEDIUM이고 Must Fix 없으면 → `/mr`로 MR/PR description 작성
- 아키텍처 경계 위반 발견 시 → `/analyze` 추가 실행 권장

## 사용 예시

```bash
/review                      # 현재 브랜치 전체 리뷰
/review apps/web             # 특정 모듈만
/review 9d29697              # 특정 커밋만
/review origin/main..HEAD    # 레인지 리뷰
```

## 주의
- **에이전트가 코드를 수정하지 않도록** 프롬프트에 "read-only 리뷰"임을 명시.
- 에이전트 결과가 비정상(빈 리포트 / 포맷 이탈)이면 재시도하지 말고 그 상태 그대로 사용자에게 노출 + 원인 한 줄 첨언.
- 이 커맨드는 **로컬 diff 기반** 리뷰다. 원격 MR/PR 코멘트가 필요하면 별도 도구를 사용한다.
