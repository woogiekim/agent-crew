결론

실제 시나리오 테스트는 PASS다. 작업 A에서 남긴 project memory가 작업 B에서 Recall되어 memory.md에 들어갔고, 그 기억이 pipeline.json의 /stages/0/tdd_parallel 변경으로 추적됐다. 이후 applied feedback이 전송됐고, Reviewer NEEDS_CHANGES에서는 validated가 차단되며, 최종 APPROVED 후 validated가 1회 전송됐다.

실행 흐름

1

작업 A

중요 AAR를 mem-project-aar project memory로 seed했다.

2

작업 B Recall

Supervisor 경로로 Recall을 실행하고 memory.md를 생성했다.

3

산출물 적용

pipeline.json에 tdd_parallel=true를 반영했다.

4

Usage 기록

memory-usage.json에 적용 memory와 locator를 기록했다.

5

Feedback

applied 후 최종 승인 시 validated를 전송했다.

6

다음 Recall

다음 검색에서 적용/검증 카운트가 ranking signal로 반영됐다.
